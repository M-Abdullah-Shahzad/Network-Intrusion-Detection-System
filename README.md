# Network Intrusion Detection System (NIDS)

A Streamlit application and notebook-based experiment for binary network-flow classification using the UNSW-NB15 dataset. The project compares K-Nearest Neighbors (KNN), Gaussian Naive Bayes, and K-Means clustering.

## Implemented

- One-hot feature preparation with a saved training feature schema.
- StandardScaler fitted on the training split and reused for test and inference data.
- KNN and Gaussian Naive Bayes supervised classifiers.
- K-Means unsupervised clustering.
- Evaluation against the supplied UNSW-NB15 testing split.
- Streamlit CSV inspector for network-flow records.
- Jupyter notebooks for model experiments and comparison.

## Dataset setup

The dataset files are not stored in this repository. Download the UNSW-NB15 training and testing CSV files from the dataset's official distribution and place them here:

    data/
      UNSW_NB15_training-set.csv
      UNSW_NB15_testing-set.csv

Optional environment variables: NIDS_TRAIN_PATH, NIDS_TEST_PATH, and NIDS_MODEL_DIR (defaults to models).

## Install

    python -m venv .venv
    # Windows PowerShell
    .\.venv\Scripts\Activate.ps1
    # macOS / Linux
    source .venv/bin/activate
    pip install -r requirements.txt

## Train and evaluate

    python train_and_save_models.py

The script fits the scaler and models using the training CSV, aligns the test CSV to the training one-hot feature columns, and calculates accuracy, precision, recall, and F1 on the held-out test CSV.

It creates local files under models/: scaler.pkl, knn_model.pkl, naive_bayes_model.pkl, kmeans_model.pkl, feature_columns.json, raw_feature_columns.json, and metrics.json. These generated artifacts are ignored by Git. The large KNN model is not stored in the repository.

## Run the dashboard

    streamlit run app.py

The Held-out Model Evaluation tab reads metrics generated by the training script. The Traffic CSV Inspector accepts a CSV with the UNSW-NB15 feature schema and aligns columns to the saved training schema before inference.

For supervised KNN and Naive Bayes outputs, label 1 is displayed as Attack and 0 as Normal. K-Means is unsupervised: the dashboard displays cluster IDs and does not treat a cluster number as an attack label.

Run notebooks from the repository root after placing the CSV files in data/.

## Tests

Install development dependencies and run `python -m pytest -q`.

## Methodology notes and limitations

- The training script uses the provided training and testing files; the test split is not used to fit the scaler or models.
- One-hot encoded test and inference columns are reindexed to the training feature schema, preventing feature-order mismatches.
- K-Means cluster IDs are arbitrary and require separate analysis before assigning a security meaning.
- The dashboard accepts full CSV flow records. It does not synthesize a full network packet from a handful of numeric fields.
- Results are dataset-specific and should not be interpreted as production network detection performance without validation on representative live traffic, class-wise analysis, threshold tuning, and operational testing.

## Repository hygiene

Raw datasets and generated model binaries are excluded from Git. Run the training script to recreate local artifacts.
